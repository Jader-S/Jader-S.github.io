> 2026 年 11 月 13 日。我这个作品站有五套主题，切换是整页导航。有天顺手切了一圈，发现除了蓝图，其余四个全是空白。第一反应是代码回归，第二反应是缓存污染，两个判断都不完整。

## 现象长什么样

用 Chromium 把五条路径各跑一遍，抓到的信号很一致：

- 四个空白主题的 `document.scrollHeight` 都是 900——正好等于视口高度，**说明页面根本没有正文**；
- 每个都有一组 404：`/_next/static/chunks/app/<theme>/page.js` 和 `page.css`；
- HTML 里能看到 `Bail out to client-side rendering: next/dynamic`，也就是首屏完全依赖客户端分块补齐，分块没了就什么都不剩；
- 蓝图之所以正常，不是它代码特殊，是它的分块恰好还在。

## 第一次误判：以为是缓存污染

早些时候跑过一次 `next build`，生产产物和开发产物落在同一个 `.next`。我判断是两类分块混在一起导致路由级 chunk 缺失，于是杀进程、`rm -rf .next`、干净重启。

**仍然复现**，而且新生成的 `.next/static/chunks/app/` 下压根没有那四个主题的目录。这说明不是「缓存里有旧文件」，是「客户端编译根本没发生」。

## 真正的根因：我起的服务器没起来

翻启动日志才发现，那次「干净重启」的 `next dev -p 3000` 报的是 `EADDRINUSE: port 3000 already in use`。我没看输出，只用 `curl` 探了一下 200 就认为成功——但那个 200 是**前一天遗留的僵尸 dev server**返回的。

实际情况是：一台僵尸占着 3000，另一台遗留进程占着 5555，两台共用同一份 `.next`；我在它们还活着的时候把 `.next` 删了，它们的状态彻底损坏，也再没有为那几个主题生成分块。清理时 `pkill -f "next dev"` 只杀了包装进程，`next-server` 子进程还留着，所以「杀过了」不等于「杀干净了」。

## 定位手法比结论更值钱

- **按端口找进程，不按命令行猜**：Windows 下用 `Get-NetTCPConnection -LocalPort 3000 | Where-Object State -eq 'Listen'` 拿 `OwningProcess`，再 `Stop-Process -Id ... -Force`。顺带踩一个坑：PowerShell 里 `$pid` 是保留字，别拿来当变量名。
- **确认新服务器真的 bind 成功**：输出里要有 `Ready`，不能只看 `curl 200`。旧进程同样会返回 200，这是这次骗过我的地方。
- **顺序**：杀净 3000 / 5555 / 3137 → 清 `.next` → 单台重启 → 预热五条路由触发编译 → 再跑浏览器验证。做完，三个主题立刻恢复。
- 之后跑 `next build` 也要先杀净 dev，否则 `.next/trace` 会报 EPERM 文件占用。

## 两个顺带的误判

**太空主题其实是误报。** 我拿 `body.innerText.length` 当「有没有内容」的判据，但 astra 是一整屏 R3F 3D 场景，DOM 里几乎没有文本，量出来接近 0 就被判定成空白。看截图才确认它渲染得好好的。**纯 DOM 文本量不能用来判断 Canvas 应用是否渲染。**

**但它确实有个真 404。** 星球贴图按 `id` 拼路径 `textures/planets/<id>.jpg`，而「联系我」这颗星球 id 是 `contact`，目录里只有 `about/blog/demos/home/projects.jpg`。加载器本来就有程序化兜底，缺图不影响画面，但每次都发一次失败请求、污染控制台。修法是加一份「已知贴图」清单：不在清单里的 id 直接走兜底，**不发网络请求**。

还有一条 R3F 的 `Attempted to synchronously unmount a root` 开发期警告。我用 `git stash` 回到改动前的基线复跑，同样复现——判定为既有架构警告，不是本轮引入，不修。这种「回基线复现一次」的动作很便宜，能省掉一堆无谓排查。

## 收敛

- 「某些页面空白、某些正常」优先查**进程 / 端口 / 缓存目录**，再查代码。分块 404 基本不可能是业务逻辑写错。
- 验证服务器状态要看**它自己的启动输出**，不要用「端口有响应」代替。
- 多环境共存时，把 dev 与 build 的产物目录隔离（这个项目现在是 `.next-dev` / `.next`），能从根上少一半这类问题。
