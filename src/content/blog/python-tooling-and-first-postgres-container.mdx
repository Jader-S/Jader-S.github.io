> 2026 年 7 月 14 日到 22 日，我在 `python-for-agent` 这个工程里做的事，说出来一点也不酷：装环境、发个包、连上数据库。但后来好几个让我卡半天的坑，根子都在这一周有没有把地基打正。

## 用 uv 把 Python 版本收进项目里

以前我习惯 pyenv 管版本、virtualenv 管环境，两套配置各管各的，项目一多就开始漂。这次换成 uv：`uv python pin` 把版本写进 `.python-version`，`uv venv` 建本地环境，`uv sync` 按 lock 装依赖——三个动作都落在**项目目录**里，谁 clone 谁复现。

更进一步，我把 Monorepo 里的 `shared`、`agents` 用 `pyproject.toml + uv build/publish` 构建并推到阿里云制品仓库，顺序上先 `shared` 后 `agents`，因为后者依赖前者。这一步逼我把包边界想清楚：哪些是公共能力，哪些是业务装配。发布到私有仓库听着隆重，实际解决的是一个很朴素的问题——别再靠「把某个目录塞进 `PYTHONPATH`」来共享代码。

剩下的时间做了些看起来像作业的练习，但后面反复用到：`asyncio` 的 `gather` / `TaskGroup` / 异步上下文手写一遍；`debugpy` 配 VSCode attach（监听 5678，编辑器连上去打断点），Monorepo 里能直接断到子包；还有 retry、上下文管理器这类模板，沉淀成可复用代码，后面每门课直接抄。

## 第一个「容器删了数据还在」的瞬间

7 月 22 日转到 `database`。Windows 上先把 Docker Desktop + WSL2 / 虚拟机平台跑通，然后起 PostgreSQL 16 和 pgAdmin 4 两个容器。

真正给我留下印象的是**数据卷挂载**：我删掉 PG 容器、重新 `docker run` 挂回同一个卷，表和数据都还在。那一刻「容器是临时的、数据是持久的」从一句口号变成了手感。之后按课件把电商的表结构过了一遍——一对多、多对多、外键策略，DDL 手写一遍比看十遍都清楚；pgAdmin 则负责「我能看见我建了什么」。

顺手把课程仓 fork 到自己的 Gitee，官方更新走 `fetch upstream` 合并。这件事当时只觉得是流程，后来多仓并行时救了我好几次。

## 这一周真正的产出

没写出任何能演示的东西，但确定了后面所有工程的默认姿势：**版本、依赖、解释器、数据，全都跟着项目目录走**。
